# DEC-20260905-01: Pin to Node 24 LTS

Status: Active
Last modified: 2026-09-05
Date: 2026-09-05
Context owner: (workflow harness repo)

## Context

The repo advertises a minimum Node version via `package.json` `engines`
and pins a CI version via `.github/workflows/publish.yml` `setup-node`.
These were inconsistent going into 0.6.0: `engines` declared `>= 22.0.0`,
but CI was pinned to `node-version: 20`. As of 2025-09-19 GitHub Actions
began deprecating Node 20 on hosted runners and forced upgrades to a
higher version when the workflow pin requested 20 — meaning CI was
silently running on whatever the runner substituted, not the version
we asked for or advertised.

| Version | LTS Start | LTS End | Notes |
|---------|-----------|---------|-------|
| 20.x | 2023-10 | 2026-04 | Maintenance LTS; deprecated on GH runners |
| 22.x | 2024-10 | 2027-04 | Was our engines minimum; was never CI pin |
| 24.x | 2025-10 | 2028-04 | Current Active LTS; what CI is actually running |
| 26.x | (future) | — | Not yet LTS |

| Option | Aligns with what CI actually runs | Consumer cost | LTS runway |
|--------|-----------------------------------|---------------|------------|
| **Pin CI to 24, bump engines to >= 24** (chosen) | yes | requires Node 24+ | until Apr 2028 |
| Pin CI to 22 (current LTS, was engines min) | requires forcing past runner deprecation | requires Node 22+ | until Apr 2027 |
| Pin CI to 24, keep engines at 22 | yes | unchanged | mismatch: tests on 24, advertise 22 |

## Decision

**Pin everything to Node 24.** CI runs on Node 24 explicitly
(declared, not forced), `engines` advertises `>= 24.0.0`, and the
release notes for 0.6.0 note the bump. The 0.5.1 release note saying
"Node 22.0.0 is now the minimum supported runtime" remains accurate
as a historical record of what shipped in 0.5.1 and is **not edited**.

## Consequences

- (+) CI tests against the advertised minimum — no more silent
  forced upgrades producing drift between CI reality and declared
  policy.
- (+) Aligns with the LTS the runners are already forcing, so the
  deprecation warning stops appearing in CI logs.
- (+) Consumers have ~2.5 years before Node 24 reaches EOL (Apr 2028)
  to migrate or stay on 0.5.x.
- (-) Drops support for Node 20 and 22 in the next minor (0.6.0).
  Currently zero consumers exist (per KTLO-20260902-01 acknowledgment
  that 0.5.1 failed to publish), so the breaking effect is theoretical.
- (-) The next LTS migration (Node 26) will require the same kind of
  bump; consider adding a KTLO or calendar reminder ~6 months before
  EOL.

## Follow-ups / escape hatch

- If a real consumer on Node 22 surfaces before the 0.7.0 cut, consider
  a 0.6.x patch release that documents Node 22 as the supported
  floor (and re-pin CI accordingly). The current decision is the
  forward-looking default, not a permanent one.
- Plan WP-04 (0.6.0 version bump) should mention "Node 24.0.0 is now the
  minimum supported runtime" in its release note (mirroring the
  v0.5.1.md format) so the change is visible to anyone reading
  release notes without diving into this DEC.
