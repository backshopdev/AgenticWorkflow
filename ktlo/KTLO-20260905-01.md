## Status

## Description

The Implementor agent was introduced in PLAN-20260904-02 WP-02 with a
skill allowlist that initially mirrors document-author's allowlist. The
two agents will likely diverge over time: some skills in document-author's
allowlist may not be relevant for executable implementation work; some
skills relevant to implementor (e.g., framework-specific implementation
skills) may not be relevant for document-author's prose work. The
current mirroring should be reviewed after WP-02 lands to identify
appropriate per-agent allowlists.

## Benefits

- Each agent's allowlist reflects its actual scope of work.
- Reduced cognitive load: implementor doesn't see skills it cannot use.
- More accurate skill loading patterns in completion packets.
- Clearer audit trail of which expertise applies to which task type.

## Challenges

- Identifying which skills truly don't apply to both agents requires
  empirical observation over multiple WP-02+ tasks.
- Some skills may be genuinely cross-cutting (e.g., `peer`, `security`,
  `design-for-testability`); need judgment about whether to remove or keep.
- The handoff's progressive specialization principle suggests some
  skills should specialize rather than be shared; need to identify which.
